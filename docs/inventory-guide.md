# מדריך המלאי — HighTide Vintage

> ## ⚠️ קרא את זה קודם — המלאי עבר ל-Cloudflare
>
> המדריך הזה נכתב כשהמלאי ישב ב-Supabase. בספטמבר 2026 הכול עבר ל-**Cloudflare D1**,
> ומה שכתוב כאן על Supabase — דשבורד, Storage, `service_role`, Table Editor — **כבר לא קיים**.
> **חלק א׳ (הפעלה ראשונה) הוא היסטוריה בלבד. אל תריץ ממנו כלום.**
>
> מה שתקף היום נמצא בשני מקומות: הפרק **"דרופ שלם חדש"** למטה, שעודכן, והטבלה כאן:
>
> | מה | איך |
> |---|---|
> | להוסיף פריטים (דרופ חדש או פריט בודד) | תמונות לתיקייה + שורות באקסל + `npm run upload-drop` |
> | לסמן פריט כנמכר | `python scripts/mark_sold.py 63` |
> | למחוק פריטים | `python scripts/reset_inventory.py` (או ההרצה האוטומטית ב-1 וב-15) |
> | לבדוק שהכול תקין | `python scripts/healthcheck.py` |
>
> אין יותר דשבורד שמעדכנים בו ביד: **האקסל והתיקיות הם המקור**, והפקודה מעלה מהם.

## חלק א׳ — הפעלה ראשונה (פעם אחת בלבד)

### 1. הרץ את הסכימה

דשבורד Supabase → **SQL Editor** → New query → הדבק את התוכן של [`supabase/schema.sql`](../supabase/schema.sql) → **Run**.

לפני שאתה מריץ את שלושת ה-policies האחרונים (של התמונות), צור את ה-bucket:
**Storage** → **New bucket** → שם `inventory` → **Public bucket ✅** → Create.

### 2. צור משתמשים

**Authentication** → **Users** → **Add user** → **Create new user**.
המייל שלך + סיסמה, ו-**Auto Confirm User ✅**. חזור על זה לכל מי שיעדכן מלאי.

### 3. הכן קובץ `.env`

בשורש הפרויקט, קובץ בשם `.env` (הוא ב-`.gitignore`, לא ייכנס לגיט):

```
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGci...
SUPABASE_URL=https://xxxxx.supabase.co
SUPABASE_SERVICE_KEY=eyJhbGci...
```

את כל הערכים תמצא ב-**Settings ⚙️ → API**.
ה-`anon` הוא הציבורי. ה-`service_role` מוסתר מאחורי כפתור **Reveal** — הוא עוקף כל הרשאה, אז הוא נשאר רק בקובץ הזה.

### 4. העלה את המלאי הקיים

```bash
pip install supabase
```

קודם הרצה יבשה, שרק מדפיסה מה יקרה:

```bash
python scripts/migrate_to_supabase.py --dry-run
```

אם הרשימה נראית נכונה — ההרצה האמיתית:

```bash
python scripts/migrate_to_supabase.py
```

הסקריפט מעלה 115 תמונות ויוצר 77 פריטים. ייקח כמה דקות. אם הוא נופל באמצע — פשוט תריץ שוב, הוא מדלג על מה שכבר עלה.

> **התמונות נדחסות בדרך למעלה.** כל תמונה מומרת ל-WebP ברוחב מקסימלי של 1200px — בממוצע 564KB יורדים ל-58KB, כלומר 90% פחות. לכן הנתיב בבאקט תמיד מסתיים ב-`.webp`, גם אם המקור היה `.png` או `.jpg`. המקור בתיקייה לא נגע.
>
> זה לא ייעול לשמו: העלאת מקורות היא מה ששרף את מכסת התעבורה של Supabase באוגוסט 2026 — 60MB מאוחסנים יצאו כ-56GB בחודש, פי 11 מהמכסה, והפרויקט הושבת. בנוסף כל תמונה נשמרת במטמון הדפדפן לשנה במקום לשעה.

**בדיקה:** Table Editor → `items` → **77 שורות**, מתוכן 16 מסומנות `sold`. `item_photos` → **115 שורות**.

> אם הוספת תמונות או שורות אקסל אחרי שקראת את זה — הרץ קודם `python scripts/sync_inventory.py` כדי לרענן את `src/inventory_db.json`, ורק אז את המיגרציה.

### 5. חבר את האתר

**מקומית:** `npm run dev` — המלאי אמור לעלות.

**ב-Netlify:** Site configuration → **Environment variables** → Add:

| Key | Value |
|---|---|
| `VITE_SUPABASE_URL` | `https://xxxxx.supabase.co` |
| `VITE_SUPABASE_ANON_KEY` | `eyJhbGci...` |

⚠️ בלי אלה האתר יעלה **ריק**. אחרי ההוספה — Deploys → **Trigger deploy** → Clear cache and deploy site.

### 6. סודות לאיפוס האוטומטי

GitHub → הריפו → Settings → Secrets and variables → **Actions** → New repository secret:

| Name | Value |
|---|---|
| `SUPABASE_URL` | `https://xxxxx.supabase.co` |
| `SUPABASE_SERVICE_KEY` | ה-service_role key |

## חלק ב׳ — עבודה יומיומית

הכל קורה ב-**Table Editor** בדשבורד. הוא נראה ומתנהג כמו אקסל.

### פריט נמכר

`items` → מצא את השורה → סמן ✅ בעמודה **`sold`**.

זהו. הפריט יסומן "נמכר" באתר וכפתור הווצאפ ייחסם. `sold_at` יתמלא אוטומטית בתאריך.

> הפריט **נשאר** באתר עם חותמת "נמכר" עד האיפוס האוטומטי ב-1 או ב-15 לחודש. ככה סיכמנו.

### מידות הפריט — `waist_cm` ו-`length_cm`

התווית על בגד וינטג׳ כמעט חסרת משמעות: 32 של ביליבונג מ-2003 ו-32 של קוויקסילבר מ-2009 הם לא אותו מכנס. מה שעונה ללקוח זה סרט מדידה.

**איך מודדים** — הבגד שטוח על שולחן, כפתור סגור:

| עמודה | מה מודדים |
|---|---|
| `waist_cm` | **רוחב** החגורה מקצה לקצה. לא היקף — האתר מכפיל ב-2 לבד |
| `length_cm` | מהחגורה עד סוף המכנס |

מספרים שלמים, בלי יחידות. `42` ולא `42 ס"מ`.

**מה הלקוח מקבל:** טבלת מידות בעמוד הפריט, ושדה שבו הוא מקליד את מידת הג׳ינס שלו ומקבל תשובה — *מתאים / צמוד / רפוי / קטן מדי*.

> פריט בלי המידות האלה פשוט לא מציג את הבלוק. אין המצאות, אין הערכות. תמלא כשיש לך זמן, פריט-פריט.

### שינוי מחיר / שם / מידה

לחץ על התא, שנה, `Enter`. רענן את האתר וזה שם.

### פריט במבצע

מלא את **`original_price`** במחיר הישן, והשאר את `price` במחיר החדש:

| `price` | `original_price` | מה רואים באתר |
|---|---|---|
| `150` | ריק | ₪150 |
| `150` | `220` | **₪150** באדום מודגש, ~~₪220~~ באפור, וחותמת **SALE** לידם |

להוריד מהמבצע — פשוט מרוקנים את `original_price`.

ברגע שיש ולו פריט אחד במבצע בקטגוריה, מופיע בסינון גם **"מבצעים: במבצע בלבד"**.

**מהאקסל:** הוסף עמודה בשם **`מחיר לפני`** עם המחיר שלפני ההנחה. פריט בלי ערך שם — מחיר רגיל, בלי חותמת.

| מספר פריט | שם | מחיר לפני | מחיר |
|---|---|---|---|
| #97 | QuickSilver | 250 | 150 |
| #3 | O'Neill | | 250 |

⚠️ `npm run upload-drop` **מדלג** על פריטים שכבר עלו, אז הוספת מחיר לגיליון לא תעדכן אותם. לזה יש:

```bash
python scripts/migrate_to_supabase.py --update-prices
```

הוא נוגע **רק** ב-`price` ו-`original_price`. מה שסימנת ידנית בדשבורד — `sold`, שם, מידה — נשאר.

### דרופ שלם חדש — הדרך המהירה

זו הדרך להוסיף פריטים, בין אם זה פריט אחד או שלושים. **האקסל והתמונות הם המקור**, והפקודה מעלה מהם ל-Cloudflare.

**1. התמונות** — לתוך `assets/inventory/`, בתיקייה של הקטגוריה:

| תיקייה | הקטגוריה באתר |
|---|---|
| `bordies` | בורדיז |
| `T-shirts` | חולצות |
| `women` | נשים |
| `accessories` | אקססוריז |

שם הקובץ הוא **מספר הפריט בלבד**: `147.jpg`. זווית נוספת מקבלת אות: `147a.jpg`, `147b.jpg`.
jpg, png או webp — לא משנה. התמונה המקורית אף פעם לא נדרסת; נוצר ממנה עותק דחוס בנפרד.

**2. השורה באקסל** — בגיליון המתאים ב-`assets/inventory/excel/`, עם העמודות
`מספר פריט` | `שם` | `מידה` | `תאריך` | `מצב` | `מחיר`. למבצע — עמודת `מחיר לפני` עם המחיר הישן.
העמודות מזוהות לפי הכותרת, אז אפשר להזיז ולהוסיף עמודות בלי לשבור כלום.

**3. הפקודה:**

```bash
npm run upload-drop
```

לראות מה היא תעשה, בלי לשנות כלום:

```bash
python scripts/sync_inventory.py && python scripts/upload_drop.py --dry-run
```

ההרצה היבשה מדפיסה שלושה דברים ששווה להסתכל עליהם:

- **מה ייכנס לחנות** — כל פריט חדש בשמו ובמספרו.
- **פריט בלי תמונה** — הוא לא יעלה. לחנות אין מה להציג עליו.
- **תמונות בלי שורה באקסל** — פריטים שצולמו ומוספרו ואף פעם לא הוקלדו. הם לא בחנות, ולא יעלו, עד שתהיה להם שורה.

הפקודה בטוחה להרצה חוזרת: פריט שכבר קיים מתעדכן ולא מוכפל, והסימון "נמכר", מונה הצפיות ותאריך הדרופ שכבר נקבע — נשארים כמו שהם. היא אף פעם לא מוחקת פריט; מחיקה היא `reset_inventory.py`.

> **מה הפקודה עושה בפועל,** לפי הסדר: קוראת את כל גיליונות האקסל → מעלה את הפריטים ל-Cloudflare →
> דוחסת את התמונות לשלושה גדלים → בונה מחדש את עותק החירום שנשלח עם האתר → מייצרת תמונות לשיתוף →
> מעדכנת את מפת האתר. בסוף צריך רק `git add . && git commit && git push` כדי שהאתר ייבנה מחדש.

### פריט חדש בודד

אותה דרך בדיוק: תמונה לתיקייה, שורה באקסל, `npm run upload-drop`. אין טעם לעשות משהו אחר לפריט בודד —
הפקודה מדלגת על כל מה שכבר קיים ומעלה רק את החדש.

> שמות התמונות: `47.jpeg` היא הראשית של פריט 47, `47a.jpeg` הזווית השנייה, `47b.jpeg` השלישית.
> התמונה הראשית היא זו שמופיעה על הכרטיס בחנות.

### פריט בלי קטגוריה

פריט שעמודת `category` שלו ריקה **לא מוצג באתר**. זה מכוון — ככה אפשר להעלות סחורה מראש ולפרסם אותה כשמוכנים. תבחר קטגוריה והוא עולה.

⚠️ אם כבר קיים פריט עם אותו `num` באותה קטגוריה, השמירה תיכשל (`duplicate key`). תן מספר אחר.

## מה לא לעשות

- **אל תמחק תמונה מ-Storage בלי למחוק את השורה ב-`item_photos`** — הפריט יופיע באתר עם תמונה שבורה.
- **אל תשנה `id`** — הוא מקשר בין הפריט לתמונות שלו.
- **אל תשתף את ה-`service_role` key.** בשום צ'אט, בשום קובץ שנכנס לגיט. מי שיש לו אותו יכול למחוק לך את כל המלאי.
- **אל תוריד את הסימון Public מה-bucket** — כל התמונות באתר ייעלמו.

## אם משהו נשבר

| מה קורה | למה | מה לעשות |
|---|---|---|
| האתר ריק, אין שגיאה בקונסול | משתני הסביבה חסרים ב-Netlify | הוסף אותם ו-Trigger deploy |
| `Supabase is not configured` בקונסול | אין `.env` מקומי | צור אותו לפי חלק א׳ שלב 3 |
| תמונות שבורות | ה-`path` ב-`item_photos` לא תואם ל-Storage | השווה את הנתיב המדויק, כולל הסיומת |
| פריט לא מופיע באתר | אין לו `category`, או אין לו שורה ב-`item_photos` | בדוק את שניהם |
| שינוי בטבלה לא מופיע באתר | הדפדפן מציג עותק שמור | רענון קשיח: `Ctrl+Shift+R` |

**הגיבוי הישן:** האקסלים ב-`assets/inventory/excel/` והתמונות ב-`assets/inventory/` נשארים בגיט כרשת ביטחון. אל תמחק אותם עד שהמערכת רצה חודש בלי תקלות.
